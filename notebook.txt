## Notes
 
- Persistence
- 2-Fault Tolerance
- Multi-machine readiness (simulated if needed)
- No shared storage
- Bonus: Log inspection & system recovery

For 2-fault tolerance, we should have 3 servers on different ports.
Each follower is an independent replica with its own persistent storage and message logs. There is no shared store.

The leader coordinates replication. Leader election is done based on highest id

Stop the leader (Ctrl+C), restart server
    - Leader is restarted, but followers are still running.

Reconnect with the client as bob
Check the inbox — the message from alice should still be there

All user and message data persisted through a crash using local log replay

Kill two follower processes (close their terminals or Ctrl+C), send a message
With only one replica left, we can still reach a quorum, so the system remains available

Restart the two followers
Each restarted follower replays its log and catches up. No central state or shared database is needed

This should be a distributed chat system that’s fully persistent, 2-fault tolerant, and has no shared storage. 
It can be deployed across multiple machines or run locally for testing. 
Logs ensure message durability, and quorum-based replication ensures consistency.
